Page-replacement benchmarks

Measuring eviction-policy trade-offs in a demand-paged Pintos kernel — part of unix-kernel-subsystem.

The kernel pages on demand and chooses its eviction policy at boot (-evict=clock|fifo|random). These numbers are the kernel's own KSTAT counters over 10 seeds per configuration, collected by scripts/bench.sh and summarised by analyze.py. Design rationale is in ADR-003.

Running this curve originally surfaced two concurrency bugs in the paging code — a free-before-read race in swap_in and a load-during-eviction window — that only the benchmark's parallel stress triggered. Both are fixed; every memory size now passes. Write-up: BUGS-FOUND.md.

Theory: simulation against Belady's optimal

A trace-driven simulator (simulate.py) runs the same reference strings under FIFO, LRU, CLOCK and OPT (Belady's optimal, the unbeatable lower bound). It reproduces Belady's anomaly — FIFO faulting more with more frames — which LRU and OPT, as stack algorithms, never do.
