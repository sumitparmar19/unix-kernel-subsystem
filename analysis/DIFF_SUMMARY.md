# Sumit's changes vs stock Pintos

**Baseline (exact):** Stanford `pintos-anon` commit **`9f013d0`** (2021-04-15, John Ousterhout,
"Updated to use Bochs 2.6.11"), taken from `github.com/fghanei/pintos`, a clone of the official
`git://pintos-os.org/pintos-anon` history.

**How it was chosen:** I compared Sumit's tree with each of the last 60 upstream commits and counted
the files that differ. `9f013d0` and `85da529` tie at 13. Only `9f013d0` has the Bochs 2.6.11
patches found in Sumit's `misc/`. The newer upstream master has later fixes to `devices/rtc.c` and
`lib/random.c` (2021-05-29) that Sumit's tree does not have. Against `9f013d0`, every non-student
file matches byte for byte (CRLF ignored), and `tests/` is untouched.

**Source analysed:** `sumitkis@buffalo.edu_1_pa1_task2.zip` (uploaded 2026-10-15). File dates
2025-11-22 to 2025-11-24. No `.git` folder, so there is no commit history. Authorship rests on
Sumit's word plus the absence of any other name in the code.

\* `higher_prio` is written in a style the detector skips (`bool higher_prio(...) {` with the
return type on the same line). It is new code by Sumit.
In `process.c`, `load_segment`, `process_activate` and `start_process` show as "changed" only
because stock comments were removed or shortened; their code is identical (verified with comments and
whitespace stripped). `install_page` was rewritten to equivalent logic. `validate_segment` **dropped
one stock check**, the wrap-around test `if (phdr->p_vaddr + phdr->p_memsz < phdr->p_vaddr) return false;`.
No test covers it. A crafted ELF whose segment wraps past the top of the address space now passes
validation. `load_segment` then walks into kernel addresses, and `ASSERT (is_user_vaddr (upage))` in
`pagedir_set_page` panics the kernel (likely outcome, from reading the code; not run).
`sema_self_test` lost its two `printf` lines.
