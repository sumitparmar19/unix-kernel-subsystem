# Trace-driven page-replacement simulation

Generated by `analysis/simulate.py`. Page faults for each policy over the same reference string, sweeping the number of physical frames. **OPT** (Belady's optimal) is the lower bound no online policy can beat; the gap above it is the price of not knowing the future.


> These reference strings are **synthetic** -- textbook patterns (`belady`, `sequential`, `loop`, `zipf`) chosen to show each policy's character, not traces captured from the kernel. Pass `--trace FILE` to feed a real captured reference string instead.

## Connection to the kernel

The kernel defaults to CLOCK (`src/vm/frame.c`). The simulation shows why: CLOCK tracks LRU closely using just one reference bit per frame instead of LRU's full ordering, so it is cheap enough to run in the fault path, yet it stays far below FIFO on skewed and looping references. CLOCK is not a true stack algorithm and so can still show Belady's anomaly on adversarial strings (above), and it is the safe default on real workloads: in the measured runs (`BENCHMARKS.md`) FIFO thrashes the write-heavy mergesort past the time budget while clock always finishes. Clock is not always the fewest-faults policy -- on that same mergesort random edges it out, because rewriting every page defeats the accessed-bit heuristic -- but it never loses badly, which FIFO does.

Reproduce: `python3 analysis/simulate.py` (or `--trace FILE` for a captured reference string).
